默认已经能下载：不注册 HTTP 客户端时使用 `HttpURLConnection`，并记一条警告。要换掉某一段，在 `DownloaderConfig.Builder` 里传入另一个实现。`core` 里的接口不用改。

版本对齐：

```kotlin
dependencies {
    implementation(platform("io.github.arturoyi:fast-download-bom:1.0.2-rc"))
    implementation("io.github.arturoyi:fast-download-api")
}
```

BOM 里还有 `fast-download-cronet` 和 `fast-download-rx`。`OkHttpHttpClient` 随 `fast-download-api` 提供。

## OkHttp

```kotlin
FastDownloader.init(
    DownloaderConfig.Builder(context)
        .httpClient(OkHttpHttpClient())
        .build(),
)
```

## Cronet

原生库由应用自己提供，例如 Play 服务里的 Cronet，或 `cronet-embedded`。这里只接收已经建好的 `CronetEngine`。

```kotlin
val engine = CronetProvider.getAllProviders(context)
    .first { it.isEnabled }
    .createBuilder()
    .build()

FastDownloader.init(
    DownloaderConfig.Builder(context)
        .httpClient(CronetHttpClient(engine))
        .build(),
)
```

## 分块、校验和保活

分块、临时文件、摘要和保活也可以换。不传时用按文件大小分档、内部目录、SHA-256 / MD5，以及配置里的保活模式。

```kotlin
DownloaderConfig.Builder(context)
    .breakpointStrategy(SingleBlockStrategy)
    .integrityVerifier(ChannelIntegrityVerifier)
    .build()
```

`SingleBlockStrategy` 始终只有一块。`ChannelIntegrityVerifier` 和默认校验接受同一套摘要规则。

前台保活在 `fast-download-notify`。默认不依赖它，下载留在进程内，也不合并通知和前台服务权限。

```kotlin
dependencies {
    implementation(platform("io.github.arturoyi:fast-download-bom:1.0.2-rc"))
    implementation("io.github.arturoyi:fast-download-api")
    implementation("io.github.arturoyi:fast-download-notify")
}

FastDownloader.init(context) {
    foregroundService()
}
```

这一次调用会启动前台服务；系统拒绝时改走 WorkManager。进程被杀掉之后不会自动接着下。

## RxJava 3

再加 `fast-download-rx`：

```kotlin
request.awaitSingle(downloader)
    .subscribe({ result -> /* 成功或失败 */ }, { error -> /* 订阅本身失败 */ })
```

`progressFlowable`、`eventsFlowable` 和 `groupProgressFlowable` 对应协程里的 Flow。取消订阅会取消还在进行的 `awaitSingle`。

进程被杀掉之后不会自动接着下。下次启动靠断点，不靠前台服务或 WorkManager。
