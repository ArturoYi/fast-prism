一个 SDK 占仓库根目录的一个文件夹。FastDownload 1.0.0-rc 现在是：

```text
fast-download/
├── build.gradle.kts          # 只聚合 check
├── bom/                      # :fast-download:bom，版本对齐
├── core/                     # 模型、错误码、12 个 SPI
├── engine/                   # 下载、调度、默认实现
├── android/                  # Room、网络状态、内容 Uri
├── api/                      # FastDownloader 门面
├── notify/                   # 可选：前台服务、通知、WorkManager
├── okhttp/                   # OkHttp 客户端
├── cronet/                   # Cronet 客户端，引擎由接入方提供
├── ktx/                      # 协程和 Flow
├── rx/                       # RxJava 3
├── testing/                  # 测试夹具，不发布
└── sample/                   # Demo，不发布
```

`core`、`engine`、`okhttp` 应用 `sdk.jvm.library`，不能应用 Android 插件。`api`、`android`、`notify`、`ktx`、`rx`、`cronet` 和 Demo 使用 Android 插件。Cronet 模块只编译官方接口包，不附带原生引擎。接入方可以只依赖 `fast-download-bom`，再按需引用上面的构件，不用自己对齐版本。不依赖 `notify` 时，应用清单里不会出现通知和前台服务权限。

## 新增一个独立 SDK

彼此独立的 SDK 平铺在仓库根目录。目录名就是 SDK 名，也是它的 Gradle 路径。现在是：

```text
.
├── fast-download/      # :fast-download:*
└── album-cleaner/      # :album-cleaner，只聚合 check
```

`settings.gradle.kts` 里逐个声明。有内部子模块时写出完整路径：

```kotlin
include(":fast-download")
include(":fast-download:core")
include(":fast-download:engine")
include(":album-cleaner")
include(":album-cleaner:core")
include(":album-cleaner:storage")
include(":album-cleaner:scan")
include(":album-cleaner:sample")
```

父模块不发布，只把子模块的 `check` 收在一起。按能力拆模块，而不是再包一层门面。AlbumCleaner 的入口是 `core`，索引是 `storage`，扫描是 `scan`。Demo 只属于某一个 SDK 时，放在该目录下的 `sample/`。

Android 可发布库同时应用 `sdk.android.library` 和 `sdk.android.library.published`，并写上自己的 `group`、`version` 和 `sdkPublish.description`。纯 JVM 库应用 `sdk.jvm.library`。Demo 只应用 `sdk.android.application`。

新 SDK 不要另写一套编译环境。这三个插件会带上 `gradle/libs.versions.toml` 里的 AGP、Kotlin、compileSdk 和 minSdk，以及 JDK 17、字节码 11、core library desugaring、资源前缀，和按 `namespace` 生成的公开 API consumer rules。资源文件名必须以这个前缀开头。

`build-logic/` 留给 convention 插件，不要把业务库放进去。

## 放置某个库的子模块

子模块放在父目录下面。Gradle 路径用冒号，磁盘路径用子目录：

```text
permissions/                 # :permissions
├── build.gradle.kts
├── src/
└── lint/                    # :permissions:lint
    ├── build.gradle.kts
    └── src/
```

```kotlin
include(":permissions")
include(":permissions:lint")
```

父模块如果要依赖它：

```kotlin
dependencies {
    api(project(":permissions:lint"))
}
```

不要写成 `api("group:permissions-lint:1.2.3")`。发布时 POM 会使用子模块自己的 `group`、`artifactId` 和 `version`。

子模块可以单独发布，只要它使用 published convention，并拥有自己的版本。它也可以是不发布的内部工程，这时只应用 `sdk.android.library`。

Demo 如果只服务某一个库，同样可以放在该库目录下，但必须是 application，例如 `permissions/sample` 对应 `:permissions:sample`。仓库级 Demo 继续放在根目录的 `sample/`。

## 选择平铺还是嵌套

平铺适合彼此独立、会单独发版的库，例如 `pager` 和 `permissions`。嵌套适合一个库拆出来的实现或 lint 规则，例如 `:permissions:lint`。

变更检测按目录前缀匹配。改了 `permissions/lint` 里的文件，`:permissions` 和 `:permissions:lint` 都会被视为变更。如果两个库必须完全分开统计变更，就把它们平铺成 `permissions/` 和 `permissions-lint/`。
