一个 SDK 占仓库根目录的一个文件夹。FastDowload 现在是：

```text
fast-dowload/                 # :fast-dowload，一个 SDK，不要把 fast-dowload-* 铺到仓库根
├── build.gradle.kts         # 只聚合 check，这一阶段不发布
├── core/                    # :fast-dowload:core，纯 JVM
├── engine/                  # :fast-dowload:engine，纯 JVM
├── testing/                 # :fast-dowload:testing，测试夹具，不发布
└── sample/                  # :fast-dowload:sample，Demo，不发布
```

`core` 和 `engine` 应用 `sdk.jvm.library`，不能应用 Android 插件。Demo 只应用 `sdk.android.application`。

## 新增一个独立 SDK

彼此独立的 SDK 平铺在仓库根目录。目录名就是 SDK 名：

```text
.
├── fast-dowload/      # :fast-dowload:* 
├── pager/            # :pager
└── permissions/      # :permissions
```

`settings.gradle.kts` 里逐个声明。有内部子模块时写出完整路径：

```kotlin
include(":fast-dowload")
include(":fast-dowload:core")
include(":fast-dowload:engine")
include(":pager")
include(":permissions")
```

Android 可发布库同时应用 `sdk.android.library` 和 `sdk.android.library.published`，并写上自己的 `group`、`version` 和 `sdkPublish.description`。纯 JVM 库应用 `sdk.jvm.library`。Demo 只应用 `sdk.android.application`。

`build-logic/` 留给 convention 插件，不要把业务库放进去。

## 放置某个库的子模块

子模块放在父目录下面。Gradle 路径用冒号，磁盘路径用子目录：

```text
permissions/                 # :permissions
├── build.gradle.kts
├── src/
└── lint/                    # :permissions:lint
    ├── build.gradle.kts
    └── src/
```

```kotlin
include(":permissions")
include(":permissions:lint")
```

父模块如果要依赖它：

```kotlin
dependencies {
    api(project(":permissions:lint"))
}
```

不要写成 `api("group:permissions-lint:1.2.3")`。发布时 POM 会使用子模块自己的 `group`、`artifactId` 和 `version`。

子模块可以单独发布，只要它使用 published convention，并拥有自己的版本。它也可以是不发布的内部工程，这时只应用 `sdk.android.library`。

Demo 如果只服务某一个库，同样可以放在该库目录下，但必须是 application，例如 `permissions/sample` 对应 `:permissions:sample`。仓库级 Demo 继续放在根目录的 `sample/`。

## 选择平铺还是嵌套

平铺适合彼此独立、会单独发版的库，例如 `pager` 和 `permissions`。嵌套适合一个库拆出来的实现或 lint 规则，例如 `:permissions:lint`。

变更检测按目录前缀匹配。改了 `permissions/lint` 里的文件，`:permissions` 和 `:permissions:lint` 都会被视为变更。如果两个库必须完全分开统计变更，就把它们平铺成 `permissions/` 和 `permissions-lint/`。
