发布使用 `com.vanniktech.maven.publish` 0.28.0。jcenter/bintray 已关停，仓库不配置 Bintray。账号和 GPG 私钥放在环境变量或本机 `~/.gradle/gradle.properties`，不要提交。

FastDowload 的 `:fast-dowload:core`、`:fast-dowload:engine`、`:fast-dowload:testing` 这一阶段是纯 JVM 子模块，还没有接入发布插件。下面的 `:library` 表示「已经应用 published convention 的那个库」。

## 在本地查看坐标

```bash
./gradlew :library:printSdkCoordinates
```

独立版本模式下，版本来自该模块的 `build.gradle.kts`。加上 `-Psdk.snapshot=true` 后，`0.1.0` 会显示成 `0.1.0-SNAPSHOT`。

安装到本机 Maven 仓库：

```bash
./gradlew :library:publishToMavenLocal -Psdk.snapshot=true
```

Release 的 `publishToMavenLocal` 需要签名。没有 GPG 时，用 SNAPSHOT 做本地验证。

## 上传一个模块

SNAPSHOT：

```bash
export ORG_GRADLE_PROJECT_mavenCentralUsername="你的 token 用户名"
export ORG_GRADLE_PROJECT_mavenCentralPassword="你的 token 密码"
export ORG_GRADLE_PROJECT_signingInMemoryKey="$(cat secring.asc)"
export ORG_GRADLE_PROJECT_signingInMemoryKeyId="KEYID"
export ORG_GRADLE_PROJECT_signingInMemoryKeyPassword="私钥口令"

./gradlew :library:publish -Psdk.snapshot=true
```

Release 会在构建结束时 close staging，并 release：

```bash
./gradlew :library:publish -Psdk.automaticRelease=true
```

远程发布要带模块路径，例如 `:library:publish`。不带路径的 `publish` 会失败，这样不会把所有模块一起发出去。

SNAPSHOT 上传到 `https://oss.sonatype.org/content/repositories/snapshots/`。

Release 先进入 Sonatype staging。OSSRH 不接受直接写入 releases 仓库。`sdk.automaticRelease=true` 时，插件先 close staging，再 release。完成后构件出现在 `https://oss.sonatype.org/content/repositories/releases/` 和 Maven Central。

2021 年 2 月之后新建的 namespace 可能在 `s01.oss.sonatype.org`。这时设置 `sdk.sonatypeHost=S01`。默认 `DEFAULT` 指向 `oss.sonatype.org`。

`sourcesJar` 和 `javadocJar` 由 convention 打开。许可证、SCM 和开发者来自根 `gradle.properties` 的 `POM_*`。模块名称和说明写在 `sdkPublish`。

## 准备 Sonatype 账号

1. 在 [central.sonatype.com](https://central.sonatype.com) 注册并验证 namespace。当前 groupId 是 `io.fastdowload`。
2. 在 [oss.sonatype.org](https://oss.sonatype.org) 生成 User Token。用户名和密码对应 `mavenCentralUsername`、`mavenCentralPassword`。
3. 确认 namespace 在 `oss.sonatype.org` 还是 `s01.oss.sonatype.org`，再决定 `sdk.sonatypeHost`。
4. 修改根 `gradle.properties` 里的 `POM_URL`、`POM_SCM_*` 和 `POM_DEVELOPER_*`。
5. 可发布库同时应用 `sdk.android.library` 与 `sdk.android.library.published`。Application 只应用 `sdk.android.application`。

CI 使用 GitHub Actions secrets，workflow 会加上 `ORG_GRADLE_PROJECT_` 前缀。

| Secret | Gradle 属性 |
| --- | --- |
| `MAVEN_CENTRAL_USERNAME` | `mavenCentralUsername` |
| `MAVEN_CENTRAL_PASSWORD` | `mavenCentralPassword` |
| `SIGNING_IN_MEMORY_KEY` | `signingInMemoryKey` |
| `SIGNING_IN_MEMORY_KEY_ID` | `signingInMemoryKeyId` |
| `SIGNING_IN_MEMORY_KEY_PASSWORD` | `signingInMemoryKeyPassword` |

## 准备 GPG 密钥

Maven Central 的 Release 必须签名。SNAPSHOT 没有密钥时仍可上传；有密钥时也会签名。

```bash
gpg --full-generate-key
gpg --list-secret-keys --keyid-format LONG
gpg --export-secret-keys --armor KEYID > secring.asc
```

把 `secring.asc` 放进 `SIGNING_IN_MEMORY_KEY`。`KEYID` 使用指纹的后 8 位或后 16 位。生成密钥时的口令放进 `signingInMemoryKeyPassword`。

如果插件无法解析密钥，去掉首行 `BEGIN` 和末尾两行 `END`，再去掉换行，压成一行。不要提交 `secring.asc`。

本机 `~/.gradle/gradle.properties` 可以写成：

```properties
mavenCentralUsername=token-username
mavenCentralPassword=token-password
signingInMemoryKey=-----BEGIN PGP PRIVATE KEY BLOCK-----...
signingInMemoryKeyId=0123ABCD
signingInMemoryKeyPassword=passphrase
```

## 选择版本模式

默认 `sdk.versionMode=independent`。每个库在自己的 `build.gradle.kts` 写：

```kotlin
group = "io.fastdowload"
version = "0.1.0"
```

模块之间不共用这个版本号。`main` 发布时加 `-Psdk.snapshot=true`，上传名变成 `0.1.0-SNAPSHOT`，源码里的版本保持不变。

统一版本时在 `gradle.properties` 写：

```properties
sdk.versionMode=unified
sdk.version=0.1.0
```

convention 会忽略模块里的 `version`。成套对齐再添加 BOM，在 BOM 里使用 `constraints { api(project(":library")) }`。

tag 使用 `vX.Y.Z`，例如 `v0.1.0`。Release workflow 只发布自上次 tag 以来有变更、且声明版本正好是 `X.Y.Z` 的模块。没有模块匹配时，任务失败。

`main` 只发布本次变更的模块。`build-logic/`、`gradle/libs.versions.toml`、根构建文件和 Gradle Wrapper 的变更会视为影响全部可发布模块。只改文档或 Demo 不会发布。

手动检查发布计划：

```bash
bash scripts/publish-changed.sh --mode manual --module :library --snapshot true --dry-run
```
