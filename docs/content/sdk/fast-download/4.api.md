类型在 `com.arturoyi.fastdownload.api`。请求、状态和错误码在 `core`。回调在主线程。Java 里属性是 getter，例如 `getTasks()`；请求用 `DownloadRequestBuilder` 链式调用。

::tip
`enqueue` 和 `enqueueAll` 会等到标识算完再返回。其余任务动作放进队列后立即返回。当前状态不允许这次迁移时，命令线程记下错误，状态保持原样。
::

## 下载器

在 `Application.onCreate` 里初始化。同一个命名空间再次调用会关掉上一份。还没初始化就 `get`，会抛出 `IllegalStateException`。

```kotlin
FastDownloader.init(this) {
    namespace("media")
    concurrentLimit(3)
}

val downloader = FastDownloader.get("media")
```

`getDefault()` 取命名空间 `default`。`create(config)` 不放进全局表，用完调用 `close()`。`close()` 停掉调度和回调，这个名字可以再初始化。

| 方法 | 作用 |
| --- | --- |
| `setConcurrentLimit(limit)` | 同时下载的任务数。有效范围是 1 到 16，超出的值收到边界上。 |
| `setGlobalNetworkType(type)` | 在每条任务自己的网络要求之外再加一条。两边都满足才开始。 |
| `setGlobalSpeedLimit(bytesPerSecond)` | 全局速度，单位是字节每秒。`null` 表示这一层不限。必须大于 0。已经在读的任务在下一次领到数据时生效。和单任务上限同时存在时，按更慢的一边等待。 |
| `enableLogging(enabled)` | 更新配置快照里的 `loggingEnabled`。未注册 HTTP 客户端时，初始化仍会写出使用 `HttpURLConnection` 的警告。 |
| `config` | 当前配置快照。运行时改过的并发、网络和速度会反映在这里。 |
| `dumpState()` | 队列、重试分布和错误分布。不含完整地址。 |

数据库文件名是 `{namespace}.db`。默认下载器的命名空间是 `default`。请求没写分组时，分组名也是 `default`。这是两个字段，只是默认字符串相同。

## 配置

`DownloaderConfig.Builder` 在 `init` 时生效。

| 方法 | 默认 | 作用 |
| --- | --- | --- |
| `namespace` | `default` | 实例隔离，也参与任务标识。不能为空白。 |
| `concurrentLimit` | 4 | 至少 1。调度时收到 1 到 16。 |
| `httpClient` | `HttpURLConnection` | 换成 OkHttp 或 Cronet 时传入。 |
| `repository` | 该命名空间自己的 Room | 换成别的 `BreakpointStore`。 |
| `networkType` | 不额外限制 | 全局网络要求，规则同 `setGlobalNetworkType`。 |
| `autoStart` | `true` | `false` 时任务留在队列里，直到 `tasks.unfreeze()`。 |
| `globalSpeedLimit` | 不限 | 同 `setGlobalSpeedLimit`。 |
| `backgroundMode` | `IN_PROCESS` | 只改枚举不会启动服务。前台保活依赖 `fast-download-notify`，初始化时调用 `foregroundService()`。 |
| `breakpointStrategy` | 按文件长度分档 | 换成 `SingleBlockStrategy` 时始终一块。 |
| `filePolicy` | 内部目录里的默认策略 | 临时文件和预分配。 |
| `integrityVerifier` | 内置 SHA-256 / MD5 | 完成前核对摘要。 |
| `monitor` | 诊断日志 | 阶段耗时和错误分布。 |
| `backgroundExecutor` | 进程内计数 | 传入实例时，工厂不再使用。下载器关闭时一起关闭。 |

`outputTarget` 和 `logging` 留在配置快照上。文件写到应用内部目录，路径由请求的 `saveTo` 决定。

`foregroundService()` 会把模式设成 `FOREGROUND_SERVICE`，并注册前台保活。系统拒绝前台服务时改走 WorkManager。进程被杀掉之后不自动续跑，下次启动从断点继续。

## 请求

```kotlin
val request = downloadRequest("https://example.com/a.bin") {
    saveTo("downloads", "a.bin")
    header("Authorization", "Bearer token")
    priority(Priority.HIGH)
    group("course")
    tag("lesson", "1")
    networkType(NetworkType.UNMETERED)
    enqueueAction(EnqueueAction.UPDATE_ACCORDINGLY)
    connectionCount(3)
    bufferSize(8 * 1024)
    speedLimit(256 * 1024)
    integrity(IntegritySpec.Sha256(sha256Hex))
    retryPolicy(RetryPolicy(maxAttempts = 5))
    downloadOnEnqueue(true)
    extra("source", "catalog")
}
```

地址只允许 `http` 和 `https`，必须有主机，不能带用户信息。`saveTo` 的目录和文件名相对应用内部的 `filesDir`。文件名不能含 `/` 或 `\`。不调用 `saveTo` 时路径是 `download.bin`。

请求头不能是 `Range`、`If-Match`、`If-Range` 或 `Host`，名字和值也不能含换行。未指定时发送 `User-Agent: FastDownload/1.0.0-rc` 和 `Accept-Encoding: identity`。调用方自己写了同名头时，用调用方的值。连接超时 15 秒，读取超时 30 秒。

`tag` 和 `extra` 不进 HTTP。`tag` 可以交给 `query.getByTag`。`progressInterval` 记在请求上；主线程进度按 300 毫秒或新增 64 KiB 合并，先到先发，第一次一定会到。

| 方法 | 默认 | 约束 |
| --- | --- | --- |
| `priority` | `NORMAL` | `HIGH` 是 1，`NORMAL` 是 0，`LOW` 是 -1。数值大的先调度，相同优先级按创建时间从早到晚。 |
| `group` | `default` | 不能为空白。 |
| `networkType` | `ALL` | `ALL` 是任意已连接网络。`UNMETERED` 只走不计流量的网络。`WIFI_ONLY` 只走 Wi-Fi。没有连接时一律等待。 |
| `connectionCount` | 按长度分档 | 1 到 8。长度未知、不能随机写时只有 1 块。 |
| `bufferSize` | 8192 | 大于 0。单次从网络读入内存的字节数。 |
| `speedLimit` | 不限 | 大于 0，单位字节每秒。 |
| `downloadOnEnqueue` | `true` | `false` 时停在已登记，直到 `tasks.start`。 |
| `integrity` | 不校验 | 见下面的校验。 |
| `retryPolicy` | 额外 3 次 | 见下面的重试。 |

不写 `connectionCount` 时，小于 1 MiB 为 1 块，小于 5 MiB 为 2 块，小于 50 MiB 为 3 块，小于 100 MiB 为 4 块，再大为 5 块。

校验在临时文件改成最终文件之前进行。对不上时最终文件不会出现。

| 类型 | 条件 |
| --- | --- |
| `IntegritySpec.Sha256` | 64 位十六进制，大小写都可以。 |
| `IntegritySpec.Md5` | 32 位十六进制，大小写都可以。 |
| `IntegritySpec.ContentMd5` | 用响应头 `Content-MD5`。 |

`RetryPolicy` 的额外次数不含第一次尝试。默认第 1 次重试等 1 秒，之后乘 2，单次最多 30 秒，抖动最多 20%。`maxAttempts` 为 0 时失败后不再自动重试。网络恢复时可以提前重试。只有 `retryable` 为 true 的错误码会套用这套等待。

### 已有任务

标识由地址、相对路径和命名空间算出：对 `url|relativePath|namespace` 做 SHA-256，取前 16 字节，得到 32 位小写十六进制。文件名递增时，标识对应该次实际选中的路径。

| `EnqueueAction` | 队列里已有相同标识时 |
| --- | --- |
| `UPDATE_ACCORDINGLY` | 默认。更新请求头、优先级、标签和附加数据。断点和状态保留。 |
| `REPLACE_EXISTING` | 停掉正在写的线程，删掉目标文件和断点，用新请求重新登记。 |
| `DO_NOT_ENQUEUE_IF_EXISTING` | 返回原标识，不改已有任务。 |
| `INCREMENT_FILE_NAME` | 路径或同名文件已被占用时改名。`a.bin` 变成 `a (1).bin`，`downloads/a.tar.gz` 变成 `downloads/a.tar (1).gz`。原文件保持不变。 |

## 任务

`downloader.tasks` 上的写操作。

| 方法 | 作用 |
| --- | --- |
| `enqueue` / `enqueueAll` | 登记任务并返回标识。`enqueueAll` 放在同一个存储事务里，返回顺序和入参一致。 |
| `start` / `resume` | 放回队列。已完成、已移除、已删除不能。 |
| `pause` | 停下正在写的线程，断点保留。适用于排队、下载中、等待网络。 |
| `retry` | 同样放回队列，并清掉已经用掉的自动重试次数。 |
| `resetAutoRetryAttempts` | 把自动重试次数清零，不改变状态。次数写进仓库。 |
| `cancel` | 停掉下载。文件和断点都保留。 |
| `remove` | 移出队列。目标文件保留，临时文件和断点删掉。 |
| `delete` | 删掉记录、断点、临时文件和目标文件。 |
| `pauseAll` / `resumeAll` / `cancelAll` | 对多条任务发出同样的动作。 |
| `freeze` | 不再启动新的下载。已经在写的任务继续。 |
| `unfreeze` | 允许再次启动排队中的任务。 |

批量动作按优先级从高到低处理。已完成的任务可以 `remove` 或 `delete`。已移除和已删除没有下一步。

批量暂停和批量取消会扫到已登记的任务。已登记不能暂停，也不能取消。这种任务排在前面时，这一轮停住，排在后面的任务这次不会处理。继续已登记的任务用 `start` 或 `resume`。批量取消不包含已失败的任务；单条 `cancel` 可以。

## 分组

`downloader.groups` 按 `group` 里的名字操作。

| 方法 | 作用 |
| --- | --- |
| `get` | 挂起读取这一组的任务快照。读取在后台线程。 |
| `pause` / `resume` / `cancel` | 和任务上的批量动作相同，只作用于这一组。 |
| `delete` | 删除这一组的任务、断点和目标文件。 |

Java 没有 `groups.get` 的回调形式。按分组读取时调用 `query`，再看 `request.groupId`。

## 查询

`downloader.query` 的读取在后台线程。带 `ResultCallback` 的重载把结果送回主线程。

```kotlin
val record = downloader.query.get(id)
val active = downloader.query.getByStatus(Status.DOWNLOADING, Status.QUEUED)
val tagged = downloader.query.getByTag("lesson", "1")
val length = downloader.query.getContentLength(request)
```

```java
downloader.getQuery().get(id, record -> { /* 主线程 */ });
```

| 方法 | 作用 |
| --- | --- |
| `get(id)` | 一条任务。没有时为 `null`。 |
| `query(filter)` | 按 `DownloadFilter` 里的状态筛选。状态集合为空时返回全部，并按优先级和创建时间排好。 |
| `getByStatus` | 保留给出的状态。至少给一个。 |
| `getByTag` | 同时带有这一对标签的任务。 |
| `getContentLength` | 用 `HEAD` 读资源长度。只用地址和请求头。未知时为 `-1`。 |
| `hasActiveDownloads` | 是否还有排队、下载中或等待网络的任务。 |
| `awaitFinish` | 挂起到没有上述三类任务。已暂停和已登记不算还在下载。 |

## 监听

`addListener` 登记 `DownloadListener`。传入 `LifecycleOwner` 时，页面销毁会摘掉同一个实例。不传时留到 `removeListener` 或 `close`。重复登记同一个实例只留一份。

`addSnapshotListener` 在主线程收到整份任务列表。参数顺序是生命周期在前、监听器在后。

每个回调默认什么也不做。`ListenerBunch` 按构造时的顺序转发给多个监听器。`SimpleDownloadListener`、`AggregateProgressListener`、`BlockProgressListener`、`SpeedListener` 是空子类，用来只覆盖关心的方法。

| 回调 | 时机 |
| --- | --- |
| `onAdded` | 任务第一次出现在队列里。 |
| `onQueued` | 进入排队。`waitingOnNetwork` 为 true 时还会收到 `onWaitingNetwork`。 |
| `onWaitingNetwork` | 网络不满足要求。 |
| `onStarted` | 开始写文件，带上分块。 |
| `onConnected` | 某个分块已经连上，带上 `ContentFingerprint`。 |
| `onResumeFailed` | 已有字节不能沿用，接下来重下。 |
| `onProgress` | 已同步字节有变化。 |
| `onBlockProgress` | 单个分块的进度。 |
| `onPaused` / `onResumed` | 调用方暂停，或暂停后重新排队。 |
| `onCompleted` | 文件已经写完。 |
| `onError` | 下载失败，带 `DownloadError`。 |
| `onCancelled` | 调用方取消。文件还在。 |
| `onRemoved` | 移出队列。目标文件还在。 |
| `onDeleted` | 任务和目标文件都已删除。 |

`Progress` 的 `totalBytes` 和 `etaMillis` 为 `-1` 时表示未知。`speedBps` 为 0 表示当前没有测到速度。`blocks` 是各分块进度，单连接时可以是空列表。

`DownloadRecord` 上同名的 `totalBytes`、`speedBps`、`etaMillis` 使用同一套约定。另外还有 `downloadedBytes`、`error`、`retryAttempts`、`createdAt` 和 `updatedAt`。时间是 Unix 纪元毫秒。

`ContentFingerprint` 保留响应头原文：`eTag`、`lastModified`、`contentLength`、`acceptRanges`、`isChunked`。

## 状态

`Status.value` 一旦发布就不再改。

| 状态 | 值 | 含义 |
| --- | --- | --- |
| `ADDED` | 0 | 已登记，入队时没有要求立即下载。 |
| `QUEUED` | 1 | 等待调度。 |
| `WAITING_NETWORK` | 2 | 当前网络不满足要求。 |
| `DOWNLOADING` | 3 | 正在写入。 |
| `PAUSED` | 4 | 调用方暂停。断点保留。 |
| `COMPLETED` | 5 | 已经写完。 |
| `FAILED` | 6 | 失败。断点保留，可以再排队。 |
| `CANCELLED` | 7 | 调用方取消。文件和断点保留，可以再排队。 |
| `REMOVED` | 8 | 移出队列。目标文件保留。 |
| `DELETED` | 9 | 记录和目标文件都删除。 |

## 错误

`DownloadError` 带有 `code`、`message`、`traceId`。HTTP 失败时还有 `httpCode`。续传对不上时还有 `resumeFailedCause`。`retryable` 默认跟随错误码，一次失败可以单独覆盖。

| `ErrorCode` | 值 | 默认可重试 | 含义 |
| --- | --- | --- | --- |
| `UNKNOWN` | 0 | 是 | 尚未归类。 |
| `UNKNOWN_HOST` | 3 | 是 | 域名无法解析。 |
| `CONNECTION_TIMEOUT` | 4 | 是 | 连接或读取超时。 |
| `HTTP_NOT_FOUND` | 5 | 否 | HTTP 404。 |
| `HTTP_FORBIDDEN` | 6 | 否 | HTTP 403。 |
| `NO_NETWORK` | 7 | 是 | 当前没有可用网络。 |
| `FILE_NOT_CREATED` | 10 | 否 | 目标文件没有创建成功。 |
| `HTTP_PRECONDITION_FAILED` | 12 | 否 | HTTP 412。 |
| `SERVER_CANCELED` | 13 | 是 | 服务器中途断开。 |
| `INVALID_CONTENT_HASH` | 20 | 否 | 摘要不一致。 |
| `SECURITY_PATH_TRAVERSAL` | 21 | 否 | 目标路径逃出应用内部目录。 |
| `WRITE_IO_ERROR` | 22 | 是 | 写入本地文件失败。 |
| `INTERRUPTED` | 23 | 否 | 下载线程被中断。 |
| `CANCELED` | 24 | 否 | 调用方取消。 |
| `FILE_ALLOCATION_FAILED` | 30 | 否 | 预分配空间失败。 |
| `NO_STORAGE_SPACE` | 31 | 否 | 存储空间不足。 |

`ResumeFailedCause` 只说明这一次为什么不能从上次的偏移继续：`INFO_DIRTY`、`FILE_NOT_EXIST`、`OUTPUT_STREAM_NOT_SUPPORT`、`RESPONSE_ENTITY_TAG_CHANGED`、`RESPONSE_PRECONDITION_FAILED`、`RESPONSE_CREATED_RANGE_NOT_FROM_0`、`RESPONSE_RESET_RANGE_NOT_FROM_0`、`CONTENT_LENGTH_CHANGED`、`LAST_MODIFIED_CHANGED`、`RANGE_NOT_SATISFIABLE`。

## 协程和 RxJava

协程在 `fast-download-ktx`，包名 `com.arturoyi.fastdownload.ktx`。

| 方法 | 作用 |
| --- | --- |
| `request.await(downloader)` | 入队并挂起到结束。取消这个协程会取消下载。 |
| `progressFlow(id)` | 这条任务跨过节流阈值后的 `Progress`。收集取消时摘掉监听器。 |
| `events()` | 冷流。只包含开始、进度、完成和失败。每个收集者有自己的监听器。 |
| `groupProgress(groupId)` | 这一组已记录字节的合计。速度是 0，剩余时间是 `-1`。组里还有未知总长度时，合计总长度是 `-1`。 |

`await` 和 `awaitSingle` 只会给出 `Success` 或 `Failure`。`Success` 带最终字节数。`Failure` 带 `DownloadError`。等待期间被取消或删除，错误码是 `CANCELED`。目标文件正被别的下载写入时，任务失败，错误码是 `UNKNOWN`。

RxJava 3 在 `fast-download-rx`，同时依赖协程模块。`awaitSingle`、`progressFlowable`、`eventsFlowable`、`groupProgressFlowable` 和上面的挂起函数、Flow 对应。取消 `awaitSingle` 的订阅会取消还在进行的下载。
