### 可选依赖

::accordion

:::accordion-item{label="协程 · fast-download-ktx" icon="i-lucide-timer"}
`await` 等到结束，也可以用 Flow 看进度。

取消协程会取消这次下载。
:::

:::accordion-item{label="通知 · fast-download-notify" icon="i-lucide-bell"}
显示通知，并用 dataSync 前台服务接着下。

系统拒绝前台服务时改走 WorkManager。

通知和前台服务权限随这个模块进入清单。初始化时调用 `foregroundService()`。
:::

:::accordion-item{label="OkHttp · fast-download-okhttp" icon="i-lucide-globe"}
换成 OkHttp。

初始化时交给 `httpClient`，替换默认的 `HttpURLConnection`。
:::

:::accordion-item{label="Cronet · fast-download-cronet" icon="i-lucide-radio"}
换成 Cronet。这里只编译官方接口。

原生引擎由应用提供，例如 Play 服务里的 Cronet 或 `cronet-embedded`。

传入已经建好的 `CronetEngine`。
:::

:::accordion-item{label="RxJava · fast-download-rx" icon="i-lucide-activity"}
用 RxJava 3 订阅，例如 `awaitSingle` 和 `progressFlowable`。

取消订阅会取消还在进行的等待。

同时加上 `fast-download-ktx`。
:::

::

应用 minSdk 至少 **26**。下面按 Kotlin、Jetpack Compose 和协程来接，依赖 `fast-download-ktx`。

## 建议环境

适合已经使用 Compose 和协程的单进程应用。文件下到应用自己的目录，界面上显示进度、速度和剩余时间。安装包、离线包、课程和媒体这一类大文件，断点、失败重试和限速由 SDK 排队。

协程放在 `ViewModel.viewModelScope`。配置变更时这个范围还在，进度继续收。`progressFlow` 把一条任务的进度送进 `mutableStateOf`，Compose 直接读。停止收集时只摘掉监听，下载还在。

`await` 挂到这一次结束，结果是 `DownloadResult.Success` 或 `DownloadResult.Failure`。这个协程跟这次操作同一寿命：`ViewModel` 被清掉时，还在进行的下载会取消。离开当前页还要接着下时，用 `enqueue` 和 `progressFlow`。

用户离开界面、进程仍在、希望这次下载继续时，再加上 `fast-download-notify`。进程被系统回收之后不会接着下，下次启动从断点继续。

## 初始化

初始化放在 `Application.onCreate`，每个进程一次。默认 HTTP 客户端是 `HttpURLConnection`。

```kotlin
class App : Application() {
    override fun onCreate() {
        super.onCreate()
        FastDownloader.init(this)
    }
}
```

组合函数里用 `FastDownloader.getDefault()` 取回这一份。

## 下载

```kotlin
dependencies {
    implementation(platform("io.github.arturoyi:fast-download-bom:1.0.0-rc"))
    implementation("io.github.arturoyi:fast-download-api")
    implementation("io.github.arturoyi:fast-download-ktx")
}
```

文件写进应用内部目录。`saveTo` 接收相对路径。`enqueue` 返回任务标识，并按默认配置马上开始。`progressFlow` 在主线程发出 `Progress`。`viewModel()` 来自 `androidx.lifecycle:lifecycle-viewmodel-compose`。

```kotlin
class DownloadViewModel : ViewModel() {
    private val downloader = FastDownloader.getDefault()

    var progress by mutableStateOf<Progress?>(null)
        private set

    fun start() {
        val id = downloader.tasks.enqueue(
            downloadRequest("https://example.com/a.bin") {
                saveTo("downloads", "a.bin")
            },
        )
        viewModelScope.launch {
            downloader.progressFlow(id).collect { progress = it }
        }
    }

    fun pause(id: String) = downloader.tasks.pause(id)

    fun resume(id: String) = downloader.tasks.resume(id)

    fun cancel(id: String) = downloader.tasks.cancel(id)
}
```

这条收集会挂到 `ViewModel` 清掉。取消后文件还在。`tasks.delete(id)` 会删掉记录、断点和目标文件。`totalBytes` 和 `etaMillis` 为 `-1` 时表示未知，`speedBps` 为 0 表示当前没有测到速度。

```kotlin
@Composable
fun DownloadScreen(viewModel: DownloadViewModel = viewModel()) {
    val bytes = viewModel.progress?.downloadedBytes
    Column {
        Text(bytes?.toString() ?: "尚未开始")
        Button(onClick = viewModel::start) {
            Text("下载")
        }
    }
}
```

同一次操作要等到结束时，用 `await`：

```kotlin
viewModelScope.launch {
    val request = downloadRequest("https://example.com/a.bin") {
        saveTo("downloads", "a.bin")
    }
    val result = request.await(downloader)
}
```

界面上还要区分完成和失败时，收 `events()`。它带开始、进度、完成和失败。收集取消时摘掉监听，任务继续。

前台通知同时依赖 `fast-download-notify`，并在初始化时打开：

```kotlin
dependencies {
    implementation(platform("io.github.arturoyi:fast-download-bom:1.0.0-rc"))
    implementation("io.github.arturoyi:fast-download-api")
    implementation("io.github.arturoyi:fast-download-ktx")
    implementation("io.github.arturoyi:fast-download-notify")
}

FastDownloader.init(this) {
    foregroundService()
}
```

系统拒绝前台服务时改走 WorkManager。前台服务和 WorkManager 只在进程还活着时有用，下次启动从断点继续。
